## 适用范围

仅在项目类型为 `BI` 或 `MIXED` 且命中报表、指标、数据查询或数据服务模块时读取。普通 CRUD、交易详情和仅包含 SQL/ORM 的模块不使用本规则。

## 测试点生成

围绕“谁在什么权限和筛选条件下看到什么数据结果”去重生成业务点，至少按本次变更覆盖以下维度：

- 指标口径、粒度、去重和汇总关系；明细合计应与总计符合业务规则。
- 维度组合、默认条件、空条件、无数据、非法或超范围条件。
- 时间区间的开闭边界、业务时区、跨日/跨月和数据刷新时点。
- 租户、组织、角色、行级/列级权限及导出权限隔离。
- 分页、排序稳定性、重复请求幂等、导出与页面/API 结果一致。
- 刷新、缓存、延迟、部分数据或查询失败时的业务可见结果。

预期必须写最终业务结果，例如“指定组织和时间范围内的收入与退款数符合口径，明细合计与总计一致，且无权数据不可见”。不得只写接口成功、字段存在、SQL 执行成功或任务状态成功。

## 执行证据

沿“数据入口 → 查询/加工 → 指标或 API → 报表/导出”取证。优先使用真实测试数据和实际项目入口；允许用户明确授权的脱敏样本或 mock，但必须标注未验证的真实数据源、权限系统或刷新链路。对每条 PASS 定位指标值、数据范围、权限边界或导出内容等必要断言；缺少最终可见结果时记 `NOT_RUN`/未验证，不以 HTTP 200 或数据库有记录替代。

同一仓库的普通业务模块继续按通用规则执行，BI 证据不得替代交易、支付、用户等模块的业务断言。
